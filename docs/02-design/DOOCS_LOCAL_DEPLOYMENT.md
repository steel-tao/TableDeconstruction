## 启动方式

```powershell
npm install --prefix tools/doocs @doocs/md-cli
node tools/doocs/node_modules/@doocs/md-cli/index.js --port 8899
```

CLI 会在端口被占用时自动选择可用端口，必须以控制台最终输出的地址为准。

## CSS 策略

Doocs 的文章渲染器会依据主题配置生成内联样式，因此项目不把“外部 CSS 文件直接注入 Doocs CLI”作为已支持能力。项目保留以下两层设计：

1. `resources/css/doocs-custom-theme.css`：项目视觉规范、颜色变量和输出后处理基线。
2. Doocs 主题设置：本地编辑时用于选择主题、字号、颜色和其他排版选项。

后续渲染适配器将把项目 CSS 变量映射到 Doocs 主题配置；必要时再对最终 HTML 做受控后处理。

## Obsidian 导入面板（8800 顶层）

状态：修订中（2026-11-22），以下为落地标准。

- 位置：8800 顶层页面右下角“导入 Obsidian”按钮，点击展开面板。仅 `window.top === window` 时生效。不随页面启动自动导入。
- 数据源：3000 后端只读接口 `GET /api/obsidian/list`、`GET /api/obsidian/file?path=`，仅读取 `VAULT_PATH` 内的 `.md`，拒绝路径穿越，CORS 仅允许 `http://127.0.0.1:8800`。
- 动作：面板不再写入 8800 的 IndexedDB，也不维护导入状态。只有一个“复制正文”按钮：勾选且仅勾选 1 篇时，拉取其正文并写入剪贴板，由用户在 Doocs 编辑器中粘贴。0 篇或多篇时给出提示，不复制。
- 不写 IndexedDB 的原因：Doocs 的 `saveAll → lt()` 会删除其内存缓存之外的 `documents` 记录（见交接文档 §11 “18:02–18:27 删除路径定位”），面板直写会被删除。
- 勾选：`render()` 保留已有勾选状态；`btnAll` 使用显式状态 `selectAllOn` 切换，第一次全选，第二次全不选。
- 未做：合成 `paste` 事件注入编辑区（方案 C，已裁决暂缓）。

## 风险边界

本次验证只确认本地部署和主题能力，不确认：

- Doocs 的稳定公开渲染 API；
- 微信编辑器对所有复杂 HTML 的最终兼容性；
- 外部图片、公式和 Mermaid 在微信端的最终呈现。

这些属于后续轻量全链路验证范围，微信发布仍保留 copy/paste 兜底。

导入面板的未做项：

- `![[...]]` 图片引用：未转换，属于已知风险，后续单独评估。
- 发布回执与“已发布”自动标记：未验证，当前仅考虑手动标记；不为测试而发布真实草稿。
- 状态存储未采用最初设计的 sidecar JSON，当前使用 `localStorage`，需要写入接口时再评估。
